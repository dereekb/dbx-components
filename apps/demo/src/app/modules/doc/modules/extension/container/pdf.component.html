Drop PDFs (application/pdf) and/or images (PNG/JPEG) into the upload area. Drag the handle on each row to reorder. Pages are appended in list order; image entries become a single page sized to the image.

Each slot owns its own upload area and inline file display, and is tagged with a `slotId`. The validator directive aggregates each slot's readiness — Preview/Download stay disabled until every required slot has a ready file. Optional slots (here, Insurance Card) only block when they contain an invalid file. State-aware icons projected through the slot's header use the `dbxPdfMergeEditorFileUploadHasState` directive.

Slot capacity defaults to `1` for single-file slots and to `maxFiles` when set. Once the slot reaches capacity its `dbx-file-upload` is hidden — the user must remove an existing entry before adding more.

A single [config] object (`DbxPdfMergeEditorConfig`) drives the whole editor: `imageCompression` to downscale and (optionally) convert images on upload, `outputSizeLimits` to surface warn/error banners, plus the display options (`fileName`, `showPreviewButton`, `showDownloadButton`, `showAddFiles`, `showFileList`, `accept`, `multiple`, `downloadButton`). Any individual input still overrides the matching config field. Crossing `errorBytes` blocks Preview/Download via the store's validity gate. Each compressed entry shows a "Resized" / "Converted PNG → JPEG" chip with the original byte count.

Wrap the trigger in [dbxPdfMergeEditorStore] and (optionally) a dbxAction with a handler. The dbxPdfMergeUploadButton directive registers a DbxButtonInterceptor on the host dbx-button — when the dialog returns a confirmed Blob it calls readyValue(blob) on the surrounding action source, and the sibling dbxActionButton directive handles the resulting click and pipes working/disabled state back to the button. Close the dialog without confirming to keep the editor entries for a later attempt.

The [dbxPdfMergeEditorStore] wrapper also accepts a [config] (`DbxPdfMergeEditorConfig`) — here `imageCompression` — that flows through the button into the dialog's default dbx-pdf-merge-editor , so large images are downscaled before the merge even though the dialog's editor has no inline config.

Pass a DbxPdfMergeUploadButtonConfig whose customDialogContent renders any custom dbx-pdf-merge-editor configuration (slots, multiple uploaders, etc.) and whose uploadButtonConfig overrides the dialog footer Upload button (text, icon, color, raised, flat/stroked/tonal/basic variant flags). Leave the inner component config's injector unset so the injected component inherits the dialog's injector and sees the same store.

With pageEditing enabled, each uploaded PDF expands into its individual pages. Pages can be reordered, rotated, and marked for deletion, and the Preview and Download buttons follow those edits live. Reordering is confined to a single slot — each group is its own drop list, so a page cannot be dragged from one document into another.

sidecar additionally embeds a JSON manifest and tags every output page, so a later reader can find a specific document's pages. Membership is recorded as page tags rather than positions: tags travel with their page through any subsequent reordering, while recorded indices would go stale. The same editor with pageEditing bound to a checkbox. Add a multi-page PDF and toggle it: off renders the original file list with whole-file reordering, on renders the page list. Page edits are held in the store while the mode is off, so switching back restores them. With the mode off no source document is parsed at all — the page machinery is never instantiated.

This is what the manifest is for. Download the merged PDF from the Page editing with an embedded manifest example above, then choose that single file here: the editor reads the embedded manifest, splits the document back into the pages belonging to each section, and refills Driver’s License and Certification — original file names included. From there a single section's pages can be replaced or removed without rebuilding the whole document.

Membership is resolved from the per-page tags, so a file that was reordered after export still splits correctly. A PDF with no manifest cannot be attributed to sections and is rejected with an explanation, as is one naming a section this editor does not have ( expectedSlotIds ).
